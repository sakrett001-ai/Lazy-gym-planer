# Lazy Gym во Floot: автоматические обновления из GitHub

Исходники: `sakrett001-ai/Lazy-gym-planer`, ветка `main`.
Проект Floot: `4e32b84e-4f12-4e44-bd4a-e6f3a6f7a152`.

## Как обновляется приложение

1. Изменения сливаются в `main`.
2. Workflow `Publish checked planner release` устанавливает зависимости и Chromium, выполняет `npm run check:all`.
3. `npm run build:floot` создаёт две автономные HTML-сборки, их SHA-256 и `floot-release.json`.
4. Workflow публикует сборку в `gh-pages`, сохраняя прежние отдельные страницы и историю. Старый исходный коммит не публикуется поверх более нового `main`.
5. При открытии или перезагрузке сайт во Floot читает manifest, проверяет фиксированный репозиторий, ветку, исходный коммит, размер и SHA-256 выбранного HTML, затем запускает сборку в собственном iframe на домене Floot.

Данные приложения находятся в localStorage домена Floot. Смена версии их не удаляет.
Перенос журнала с GitHub Pages: экспортировать полную резервную копию в старой версии и импортировать её в новой.
Обновления не перезагружают уже открытую тренировку: новая версия применяется при следующем открытии или обновлении страницы.
Обновление main обычно становится доступно после прохождения workflow и обновления кеша GitHub (несколько минут).
При провале проверок manifest не меняется, сайт продолжает использовать предыдущий успешный релиз.

## Особенности размещения

Это мост с проверенным релизом GitHub, а не штатный Git-sync Floot. Рабочее приложение загружается и выполняется на домене Floot; GitHub хранит исходники и файлы релизов. Ключи доступа для публичного репозитория не нужны.
Во Floot не регистрируется собственный сервис-воркер. Сайт можно добавить на главный экран, но холодный запуск требует сети. Офлайн-PWA на GitHub Pages и автономные HTML-файлы сохраняются.

Файлы стабильной оболочки Floot сохранены в `floot/`. Изменения ядра в `src/`, переводов и сборщика распространяются автоматически. При изменении самой оболочки или серверного моста нужно синхронизировать соответствующие файлы с проектом Floot через его connector и опубликовать оболочку.

## Проверки и откат

`npm run check:all` включает регрессии, проверки манекенов, отрисовки, каталога и английских экранов.
`tools/floot-release.test.js` проверяет языки, целостность, привязку к коммиту, отказ при внешнем пути, чужом репозитории, провале проверок и недоступном сервере.
Для отката ядра сделать revert в `main`: workflow проверит и опубликует новое состояние. Старые неизменяемые сборки остаются в истории `gh-pages`.
